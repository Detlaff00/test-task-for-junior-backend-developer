# Task Service

Go-сервис трекера задач с календарным UI и поддержкой периодических задач (template + instances).

## Что реализовано

### 1) Архитектура данных

- `task_templates` — шаблон задачи и правило повторения.
- `tasks` — реальные экземпляры задач в календаре.

Ключевые поля времени (UTC):

- `all_day` (`true/false`)
- `start_time`, `end_time` (`HH:MM`, nullable)
- `scheduled_for` (дата экземпляра)

### 2) Типы повторения

Поддерживаются:

- `one_time`
- `daily`
- `monthly_day`
- `specific_dates`
- `monthly_parity`

### 3) Правила генерации (актуальная версия)

Все вычисления в UTC.

- `one_time`: только выбранная дата; если дата в прошлом -> `400`.
- `daily`: от `max(start_date, today_utc)` до `start_date + 2 months` (включительно).
- `monthly_day`: число месяца + `months_count (1..12)`; если дня нет в месяце, перенос на последний день месяца.
- `specific_dates`: только переданные даты, прошедшие (`< today_utc`) отбрасываются.
- `monthly_parity`: чет/нечет на интервале `[max(start_date, today_utc), start_date + 1 month)`.

### 4) Обновление и удаление

- При `PUT /tasks/{id}` с изменением правила: будущие сгенерированные экземпляры серии удаляются и генерируются заново.
- `DELETE /tasks/{id}?scope=single|series`:
  - `single` — удалить один экземпляр;
  - `series` — деактивировать шаблон и удалить будущие сгенерированные экземпляры серии.

### 5) Фоновая синхронизация

В `cmd/api/main.go` запущен воркер:

- стартовая синхронизация при запуске сервиса;
- затем `Sync()` каждые 5 минут.

### 6) UI (`/ui/`)

Реализован календарный интерфейс на русском:

- форма создания задач;
- чекбокс `Указать время`;
- модальное окно мультивыбора дат для `specific_dates`;
- модальное окно удаления с выбором:
  - `Удалить выбранную задачу`;
  - `Удалить все задачи этого повторения`.

## API

Базовый префикс: `/api/v1`

- `POST /tasks`
- `GET /tasks`
- `GET /tasks/{id}`
- `PUT /tasks/{id}`
- `DELETE /tasks/{id}?scope=single|series`

Swagger:

- UI: `http://localhost:8080/swagger/`
- Spec: `http://localhost:8080/swagger/openapi.json`

## Быстрый запуск

```bash
docker compose down -v
docker compose up --build -d
```

Проверка доступности:

- API: `http://localhost:8080/api/v1/tasks`
- UI: `http://localhost:8080/ui/`

## Как проверить фичу руками

### Сценарий A: specific_dates через модалку

1. Открой `http://localhost:8080/ui/`.
2. Выбери тип `Конкретные даты`.
3. Нажми `Открыть календарь дат`.
4. Выбери несколько дат и нажми `Создать задачи на выбранные даты`.
5. Убедись, что задачи появились в календаре на выбранных датах.

### Сценарий B: monthly_day + months_count

1. Выбери тип `Определённое число месяца`.
2. Укажи `Число месяца` и `Кол-во месяцев (1..12)`.
3. Создай задачу.
4. Проверь, что экземпляры создались на нужные месяцы (с переносом на последний день при необходимости).

### Сценарий C: удаление single/series

1. Нажми `Удалить` у задачи в календаре.
2. В модалке выбери:
   - `Удалить выбранную задачу` — исчезает только один экземпляр;
   - `Удалить все задачи этого повторения` — исчезают будущие экземпляры серии.

## Принятые допущения

- Хранение и расчеты времени — только в UTC.
- Для серии время (`start_time/end_time`) едино для всех экземпляров.
- Прошедшие даты не генерируются (для `one_time` в прошлом возвращается `400`).
- История выполненных/прошедших экземпляров не удаляется при `scope=series`; удаляются будущие сгенерированные.
